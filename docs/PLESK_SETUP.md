# التشغيل خلف Plesk — دومين لكل عميل

## كيف يعمل إعدادك فعليًّا

حين يُضبط جهاز البصمة **بدومين بلا منفذ**، يستخدم المنفذ **80** افتراضيًّا
— هذا منصوص عليه في بروتوكول ZKTeco:

> *"The default port is TCP 80"*

فالمسار الفعلي:

```
جهاز البصمة  →  http://almursal.onz.one/iclock/cdata?SN=...
                        (منفذ 80)
                           ↓
                     Plesk / nginx
                           ↓
        قاعدة Proxy: /iclock  →  almursal_adms:8081
```

**نتيجة مهمة:** `WEB_PORT` و`ADMS_PORT` **لا تُستعمل إطلاقًا** في هذا
الإعداد. الوسيط يصل إلى الحاويات عبر شبكة Docker الداخلية على المنفذين
الثابتين 5000 و8081.

---

## لماذا هذا أفضل من التوزيع بالمنافذ

الجهاز يرسل ترويسة `Host` مع كل طلب، فالدومين نفسه هو ما يميّز عميلًا عن
آخر:

| الدومين | يوجَّه إلى |
|---|---|
| `almursal.onz.one/iclock` | `almursal_adms:8081` |
| `alsaqr.onz.one/iclock` | `alsaqr_adms:8081` |

**دومين لكل عميل، وصفر منافذ مكشوفة.** ولا حاجة إلى جدول منافذ يُدار يدويًّا.

---

## 🔴 الثغرة التي يجب إغلاقها

بلا ضبط `BIND` يبقى للنظام **مسلكان**:

| | |
|---|---|
| `https://almursal.onz.one` | عبر Plesk — مشفّر ومحمي ✓ |
| `http://<ip-الخادم>:5002` | **مباشر، بلا تشفير، يتخطّى Plesk وشهادته** 🔴 |

أي أن بيانات الرواتب وكلمات الدخول متاحة نصًّا صريحًا لمن يعرف عنوان
الخادم. **الشهادة على الدومين لا تحمي مسلكًا يتجاوز الدومين.**

**الإغلاق:** أضف متغيّرًا واحدًا في متغيّرات البيئة:

```
BIND=127.0.0.1
```

فيصير المنفذ مسموعًا على الخادم نفسه فقط — يصله Plesk ولا يصله أحد من
الخارج.

## الإعداد الكامل لعميل

### متغيّرات البيئة في Portainer

| Name | Value |
|---|---|
| `COMPANY` | `almursal` |
| `WEB_PORT` | `5002` |
| `ADMS_PORT` | `8092` |
| `TZ` | `Asia/Kuwait` |
| **`BIND`** | **`127.0.0.1`** ← إغلاق المسلك المباشر |

`WEB_PORT` و`ADMS_PORT` يبقيان مطلوبين لأنهما يجب أن يظلّا فريدين حتى على
`127.0.0.1` — منفذان متطابقان على العنوان نفسه يتصادمان.

### قواعد الوسيط في Plesk

**الدومين → Docker Proxy Rules → Add Rule**

| URL | Container | Port |
|---|---|---|
| `/` | `almursal_web` | **5000** |
| `/iclock` | `almursal_adms` | **8081** |

> **المنافذ هنا داخلية (5000 و8081)، لا 5002 و8092.** Plesk يصل عبر شبكة
> Docker لا عبر المضيف. هذا أكثر موضع يقع فيه الخطأ.

`/iclock` هو المسار الصحيح لأن `adms_server.py` يسجّل مساراته تحت
`url_prefix='/iclock'` تحديدًا.

### الشهادة

**SSL/TLS Certificates → Let's Encrypt** ثم فعّل **Force SSL/TLS**.

---

## ⚠️ الجهاز و HTTPS

`Force SSL/TLS` يحوّل طلبات HTTP إلى HTTPS. وكثير من أجهزة البصمة **لا
تدعم HTTPS ولا SNI**، فتتوقّف عن الإرسال بعد التفعيل.

**افحص هذا مباشرة بعد تفعيل الشهادة**، ولا تفترضه:

```
Containers → almursal_adms → Logs
```

- ظهور `CDATA Received | SN: ...` ← الجهاز يصل ✓
- انقطاع الرسائل بعد تفعيل SSL ← الجهاز لا يدعم HTTPS

**إن انقطع:** استثنِ مسار `/iclock` من إجبار SSL في قواعد Plesk، أو اترك
الجهاز على `http://<ip-الخادم>:8092` داخل الشبكة المحلية — وحينها اضبط
`BIND=0.0.0.0` مع تقييد المنفذ في جدار الحماية على شبكة الأجهزة وحدها.

## عميل ثانٍ

| | العميل الأول | العميل الثاني |
|---|---|---|
| Stack / `COMPANY` | `almursal` | `alsaqr` |
| الدومين | `almursal.onz.one` | `alsaqr.onz.one` |
| `WEB_PORT` | 5002 | 5001 |
| `ADMS_PORT` | 8092 | 8091 |
| `BIND` | `127.0.0.1` | `127.0.0.1` |

كل دومين بشهادة Let's Encrypt خاصة به، وقاعدتَي وسيط خاصّتين به.

## التحقق بعد التشغيل

**١) الموقع يفتح على الدومين:**

```
https://almursal.onz.one
```

**٢) المسلك المباشر مغلق** — من جهازك لا من الخادم:

```bash
curl -m 5 http://<ip-الخادم>:5002
```

يجب أن **يفشل** (`Connection refused` أو مهلة). نجاحه يعني أن `BIND` غير
مضبوطة.

**٣) الجهاز يصل:**

```
Containers → almursal_adms → Logs   →   CDATA Received | SN: ...
```

**٤) عزل البيانات:** في **Volumes** صفٌّ لكل عميل — `almursal_hr_data`
و`alsaqr_hr_data`. صفٌّ واحد مع عميلين يعني قاعدة بيانات مشتركة.

## حلّ المشكلات

| العَرَض | السبب الأرجح | الإجراء |
|---|---|---|
| الموقع لا يفتح على الدومين | Proxy Rule خاطئة | تأكّد أن Port هو **5000** لا `WEB_PORT` |
| البصمات لا تصل | مسار `/iclock` ناقص | أضف القاعدة بالمنفذ **8081** |
| توقّفت البصمات بعد تفعيل SSL | الجهاز لا يدعم HTTPS | استثنِ `/iclock` من إجبار SSL |
| `502 Bad Gateway` | الحاوية متوقّفة | راجع Logs في `_web` |
| المنفذ المباشر مفتوح | `BIND` غير مضبوطة | أضِفها وأعد النشر |
| عميلان يريان البيانات نفسها | تشارك التخزين | راجع Volumes وأسماء الـstacks |
