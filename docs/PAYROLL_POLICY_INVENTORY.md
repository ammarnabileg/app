# جرد سياسات الرواتب — الخطوة ١

الهدف: كل قيمة أو اختيار بيأثر على الفلوس يبقى **إعداد** بتاريخ سريان. المعادلات تفضل في الكود.
القيمة الانتقالية لكل بند = **السلوك الحالي بالظبط**، فتشغيل النظام الجديد مايغيّرش أي رقم لحد ما الشركة
تغيّر إعداد بنفسها.

الأعمدة:
- **الآن:** ⚙️ إعداد موجود (`salary_settings_v2`) · 🔒 ثابت في الكود · 👤 من ملف الموظف · ⚠️ مش موجود.
- **المصدر في الكود:** `utils/payroll_engine.py` (PE) و `utils/labor_law.py` (LL).

## الخطوة ٢ المقترحة (تصميم)

- جدول `payroll_policies(key, value, scope, scope_id, effective_from, created_by, created_at, note)`:
  `scope` = `system` / `company` / `group` / `employee`. القيمة = اللي ساري في اليوم، بالأولوية
  موظف ← مجموعة ← شركة ← النظام.
- دالة واحدة `policy(key, employee, day)` يستخدمها المحرك بدل `sal.get(...)` والثوابت.
- **نسخة السياسات مع الكشف المعتمد:** عند الاعتماد بيتحفظ snapshot للقيم اللي اتطبقت (والسطر بيشاور
  عليها)، فالشهر المقفول عمره مايتغيّر بتعديل لاحق.
- **تعديل بأثر رجعي:** قبل الحفظ بيطلع الأشهر المفتوحة والموظفين المتأثرين، والمقفول مابيتلمسش.
- سجل تعديلات + صلاحية `payroll.policies` لكل قسم.
- «كيف اتحسبت؟» لكل بند: القيمة، والسياسة، ومصدرها، وتاريخ سريانها.
