# نشر عدة عملاء على مضيف واحد

## المبدأ

ملف `docker-compose.yml` **واحد لا يُعدَّل**. ما يتغيّر لكل عميل ثلاثة
متغيّرات فقط:

| المتغيّر | مثال | يجب أن يكون فريدًا |
|---|---|---|
| `COMPANY` | `alsaqr` | ✔ — منه تُشتقّ أسماء الحاويات |
| `WEB_PORT` | `5001` | ✔ — منفذ المضيف |
| `ADMS_PORT` | `8091` | ✔ — منفذ المضيف |

**المنافذ الداخلية تبقى ثابتة (5000 و8081).** كل مشروع في شبكة معزولة، فلا
تتصادم المنافذ الداخلية إطلاقًا. المتصادم هو منفذ المضيف وحده — وهو ما
يُغيَّر.

---

## عبر سطر الأوامر

```bash
# العميل الأول
COMPANY=alsaqr WEB_PORT=5001 ADMS_PORT=8091 \
  docker compose -p alsaqr up -d --build

# العميل الثاني على المضيف نفسه
COMPANY=almursal WEB_PORT=5002 ADMS_PORT=8092 \
  docker compose -p almursal up -d --build
```

أو بملف لكل عميل:

```bash
cp .env.example clients/alsaqr.env    # يُحرَّر
docker compose --env-file clients/alsaqr.env -p alsaqr up -d --build
```

**`-p` ضروري ولا يُهمَل.** هو ما يفصل التخزين: `alsaqr_hr_data` مقابل
`almursal_hr_data`. بدونه يتشارك العملاء التخزين نفسه — أي **قاعدة بيانات
واحدة لعميلين**، وهو أسوأ خطأ ممكن هنا.

---

## عبر Portainer

**Stacks → Add stack → Repository**، ثم في **Environment variables**:

| Name | Value |
|---|---|
| `COMPANY` | `alsaqr` |
| `WEB_PORT` | `5001` |
| `ADMS_PORT` | `8091` |
| `TZ` | `Asia/Kuwait` |

**اسم الـstack هو اسم المشروع** في Portainer، فاجعله مطابقًا لـ`COMPANY`
لتبقى أسماء التخزين متّسقة.

---

## جدول العملاء — يُحفظ ويُحدَّث

بلا هذا الجدول ستُعاد تعيين منفذ مستخدم، فيفشل التشغيل أو — أسوأ — يُنشر
عميل على منفذ عميل آخر.

| العميل | COMPANY | WEB_PORT | ADMS_PORT | ملاحظات |
|---|---|---|---|---|
| مثال | alsaqr | 5001 | 8091 | |
| مثال | almursal | 5002 | 8092 | |

اقتراح ترقيم: الويب من 5001 تصاعديًّا، وADMS من 8091 تصاعديًّا.

## نقاط حرجة

### التخزين هو الترخيص

معرّف التركيب محفوظ في `/app/data/.instance_id` داخل التخزين. فما دام
التخزين قائمًا:

- ✅ `docker compose up -d --build` لا يغيّر المعرّف ← الترخيص يبقى صالحًا
- ✅ إعادة تشغيل المضيف لا تؤثّر
- ❌ `docker compose down -v` **يحذف التخزين** ← تضيع قاعدة البيانات
  **والترخيص معًا**

استخدم `down` بلا `-v`. وإن حُذف التخزين فعلًا: تُستعاد النسخة الاحتياطية،
ويلزم فكّ ارتباط وإعادة إصدار الرخصة من لوحتك.

### منفذ ADMS مقصود أنه مكشوف

في بروتوكول PUSH **جهاز البصمة هو من يبتدئ الاتصال**، فلا بدّ أن يكون
الخادم مسموعًا على الشبكة المحلية. هذا ليس خيارًا بل شرط البروتوكول.

ويجب ضبط الجهاز على `http://<ip-المضيف>:<ADMS_PORT>` — أي المنفذ **الخارجي**
لهذا العميل، لا 8081.

### التوقيت

`TZ=Asia/Kuwait`. والكويت لا تعمل بالتوقيت الصيفي. ساعة النظام مصدر طوابع
الحضور، وأي انزياح فيها يزيح الأجر مباشرةً — ويظهر كـ«تأخير جماعي» غامض في
الكشف لا كخطأ تقني.

## أوامر التشغيل

```bash
docker compose -p alsaqr ps                  # حالة عميل
docker compose -p alsaqr logs -f hr_adms     # سجلّ خادم البصمة
docker compose -p alsaqr restart hr_web
docker volume ls | grep hr_data              # تخزين كل العملاء
```

نسخة احتياطية:

```bash
docker run --rm -v alsaqr_hr_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/alsaqr_$(date +%F).tar.gz -C /data .
```

**تشمل النسخة `.instance_id`** — أي أن استعادتها تعيد الترخيص أيضًا.

## الحدّ الصريح

هذا يحلّ **العزل على مضيف واحد**، ولا يحلّ ما يلي:

- **الترقية** تبقى لكل عميل على حدة
- **رؤية مركزية** غير موجودة: لا تعرف حالة كل الأجهزة دون فتح كل مشروع
- **الذاكرة** لا تزال ×3 لكل عميل

هذه هي بالضبط الأسباب التي دفعت إلى خطة المحرّك المشترك في
`DEVICE_ENGINE_PLAN.md`. ما هنا **حلّ تشغيلي فوري**، لا بديل عن تلك الخطة.
