# التشغيل من Portainer — خطوة بخطوة

## الفرق عن سطر الأوامر

| | سطر الأوامر | Portainer |
|---|---|---|
| اسم المشروع | `-p alsaqr` يدويًّا | **اسم الـstack** تلقائيًّا |
| المتغيّرات | ملف `.env` | حقول Environment variables |
| العزل | يعتمد على تذكّر `-p` | **مضمون** — لا يقبل اسمَي stack متطابقين |

**Portainer أأمن هنا:** الخطأ الأخطر في سطر الأوامر هو نسيان `-p` فيتشارك
عميلان قاعدة البيانات نفسها. في Portainer اسم الـstack هو اسم المشروع، ولا
يمكن تكراره.

---

## الخطوة ١: إنشاء الـstack

**Stacks → + Add stack**

| الحقل | القيمة |
|---|---|
| **Name** | `alsaqr` |

> **هذا الاسم هو اسم المشروع.** منه يُشتقّ اسم التخزين `alsaqr_hr_data`.
> اجعله مطابقًا لقيمة `COMPANY` تمامًا، وإلا اختلف اسم التخزين عن أسماء
> الحاويات فصار التتبّع مربكًا عند الدعم.
>
> حروف لاتينية صغيرة وأرقام وشرطة سفلية فقط.

---

## الخطوة ٢: مصدر الملف

**Build method → Repository**

| الحقل | القيمة |
|---|---|
| Repository URL | `https://github.com/ammarnabileg/app` |
| Repository reference | `refs/heads/main` |
| Compose path | `docker-compose.yml` |

للمستودع الخاص: فعّل **Authentication** وأدخل اسم المستخدم ورمز وصول
شخصيًّا.

> **بديل:** **Web editor** ولصق محتوى `docker-compose.yml`. يعمل، لكن
> التحديث حينها يدويّ في كل stack — بينما Repository يسحب التغييرات بضغطة.

---

## الخطوة ٣: متغيّرات البيئة

في قسم **Environment variables** → **Add an environment variable**:

| Name | Value |
|---|---|
| `COMPANY` | `alsaqr` |
| `WEB_PORT` | `5001` |
| `ADMS_PORT` | `8091` |
| `TZ` | `Asia/Kuwait` |

**قبل اختيار المنافذ** تأكّد أنها غير مستخدمة — من **Containers** راجع عمود
Ports، أو على الخادم:

```bash
ss -tlnp | grep -E '5001|8091'
```

`COMPANY` إلزامي: تركه فارغًا يوقف النشر برسالة صريحة بدل إنشاء حاويات
بأسماء ناقصة تتصادم مع stack آخر.

---

## الخطوة ٤: النشر

**Deploy the stack**

البناء الأول يستغرق دقائق (تنزيل الحزم وترجمتها). الشاشة تبقى على
*Deployment in progress*.

---

## الخطوة ٥: التحقق

**Containers** — يجب أن تظهر ثلاث حاويات:

```
alsaqr_web     running (healthy)
alsaqr_sync    running
alsaqr_adms    running
```

**`healthy` مهمّة:** تعني أن التطبيق يستجيب فعلًا. حاوية تعمل وخدمتها معطّلة
تظهر `running` بلا هذا الفحص.

إن ظهرت `unhealthy` أو بقيت `starting` أكثر من دقيقة: افتح `alsaqr_web` →
**Logs**.

ثم افتح `http://<ip-الخادم>:5001`.

---

## الخطوة ٦: التأكّد من عزل البيانات

**Volumes** — يجب أن يظهر صفّ لكل عميل:

```
alsaqr_hr_data
almursal_hr_data
```

**صفّ واحد مع عميلين يعني أنهما على قاعدة البيانات نفسها.** أوقف فورًا
وراجع أسماء الـstacks.

---

## الخطوة ٧: جهاز البصمة

في إعدادات الجهاز (ADMS / Cloud Server):

| الحقل | القيمة |
|---|---|
| Server Address | `<ip-الخادم>` |
| Server Port | **`8091`** — منفذ هذا العميل، لا 8081 |

راقب في **Containers → alsaqr_adms → Logs**. عند النجاح يظهر
`CDATA Received | SN: ...`.

| الرسالة | المعنى | الإجراء |
|---|---|---|
| `reason=unregistered` | الجهاز غير مسجَّل | أضِفه بالرقم التسلسلي نفسه من شاشة الأجهزة |
| `reason=over_license_limit` | بلغت حدّ الرخصة | زد الحدّ في الرخصة |

الرفض مقصود: قبول أي رقم تسلسلي يعني قبول بصمات ملفّقة.

## عميل ثانٍ

كرّر الخطوات باسم stack جديد ومتغيّرات جديدة:

| Name | `almursal` |
|---|---|
| `COMPANY` | `almursal` |
| `WEB_PORT` | `5002` |
| `ADMS_PORT` | `8092` |

**المستودع نفسه.** كل stack يبني صورة موسومة باسمه
(`hr_system_almursal:latest`) وتخزينًا خاصًّا به.

### جدول العملاء — يُحفظ ويُحدَّث

| العميل | Stack / COMPANY | WEB_PORT | ADMS_PORT |
|---|---|---|---|
| | alsaqr | 5001 | 8091 |
| | almursal | 5002 | 8092 |

## التحديث إلى نسخة جديدة

**Stacks → alsaqr → Pull and redeploy**

وفعّل **Re-pull image** عند وجوده.

**آمن على البيانات:** التخزين لا يُمسّ، وترحيل المخطط يعمل تلقائيًّا عند
الإقلاع.

**وآمن على الترخيص:** معرّف التركيب محفوظ داخل التخزين فلا يتغيّر بإعادة
البناء — وهذا ما أُصلح تحديدًا، إذ كان يُشتقّ من عنوان MAC الذي تولّده
Docker عشوائيًّا عند كل بناء فتُرفض رخصة عميل عامل.

**التحديث يخصّ stack واحدًا.** لتحديث كل العملاء كرّر لكل stack — وهذا أحد
أسباب خطة المحرّك المشترك.

---

## 🔴 ثلاثة أفعال تفقد البيانات

| الفعل | الأثر |
|---|---|
| **Stacks → Remove** مع تفعيل **Remove volumes** | يحذف قاعدة البيانات والترخيص |
| **Volumes → alsaqr_hr_data → Remove** | حذف مباشر ونهائي |
| إعادة إنشاء stack باسم مختلف | يُنشئ تخزينًا جديدًا فارغًا، والقديم يبقى معلّقًا |

**Remove بلا Remove volumes آمن:** الحاويات تُحذف والبيانات تبقى، وإعادة
النشر بالاسم نفسه تستعيدها.

## نسخة احتياطية

Portainer لا يوفّر نسخًا احتياطيًّا للتخزين. من الخادم:

```bash
docker run --rm -v alsaqr_hr_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/alsaqr_$(date +%F).tar.gz -C /data .
```

تشمل قاعدة البيانات **والترخيص** معًا، فاستعادتها تعيد الاثنين.

خذ نسخة **قبل كل Pull and redeploy** على خادم إنتاج.

## حلّ المشكلات

| العَرَض | السبب | الإجراء |
|---|---|---|
| `port is already allocated` | المنفذ مستخدم | غيّر `WEB_PORT` أو `ADMS_PORT` |
| `variable is not set` | متغيّر ناقص | راجع Environment variables |
| stack عالق على *in progress* | البناء الأول | انتظر، ثم راجع Logs |
| `unhealthy` | التطبيق لا يستجيب | Logs في `_web` |
| عميلان يريان البيانات نفسها | تشارك التخزين | راجع Volumes وأسماء الـstacks |
| البصمات لا تصل | منفذ خاطئ أو جدار حماية | راجع Logs في `_adms` |
| توقيت البصمات مزاح | `TZ` خاطئة | Console داخل الحاوية → `date` |
